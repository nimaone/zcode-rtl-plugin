# فیکس RTL زدکد — راست‌چین کردن متن فارسی در رابط چت ZCode دسکتاپ

[English](README.md) | [فارسی](#فارسی)

<a id="فارسی"></a>

**ZCode دسکتاپ** (اپ رایگان کدنویسی با هوش مصنوعی از Z.ai) متن فارسی چت را چپ‌چین و با ترتیب کلمات به‌هم‌ریخته نشان می‌دهد. اپ هیچ گزینه‌ای برای RTL ندارد و سیستم پلاگین آن هم رسماً اجازهٔ تغییر ظاهر خود اپ را نمی‌دهد — پس این پلاگین از مطمئن‌ترین راه می‌رود: یک فیکس جهت متنِ آزمون‌پس‌داده را از طریق پروتکل استاندارد دیباگ کرومیوم (CDP) داخل اپِ در حال اجرا تزریق می‌کند. **هیچ فایلی از خود ZCode تغییر داده نمی‌شود**، به همین دلیل این فیکس با آپدیت‌های اپ از کار نمی‌افتد.

**اصول طراحی (نسخه 0.4.0):**

- **حریم خصوصی به‌صورت پیش‌فرض** — سرور دیباگ **خاموش** است. شورتکات همیشگی ZCode دست‌نخورده می‌ماند؛ نه فلگ دائمی، نه پروسهٔ بک‌گراند، نه آیکن اضافه.
- **سوییچ زنده** — وقتی پورت باز باشد، `/rtl-fix off` و `/rtl-fix on` لایهٔ RTL را همان لحظه قطع و وصل می‌کنند. بدون ری‌استارت اپ.
- **یک محدودیت صادقانه** — کرومیوم فلگ `--remote-debugging-port` را فقط هنگام استارت پروسه می‌خواند؛ پس رفتن از حالت «پورت بسته» به «پورت باز» دقیقاً یک ری‌استارت اپ لازم دارد که `/rtl-fix on` خودش آن را انجام می‌دهد.

> چرا مثل پلاگین‌های dsh-arabic و dsh-rastin نیست که هیچ‌کدام از این‌ها را نمی‌خواهند؟ آن‌ها برای DeepSeek Harness هستند که API پلاگینش نقاط تزریق رسمی به UI دارد (`webserver/index-inject` و صندلی استایل). زدکد (تا نسخهٔ 3.16.x) چنین نقطهٔ توسعه‌ای ندارد — سیستم پلاگینش فقط عامل هوش مصنوعی را گسترش می‌دهد — پس پل CDP تنها راه مطمئن است. اگر زدکد روزی هوک تزریق رسمی اضافه کند، این پلاگین می‌تواند پورت را کاملاً کنار بگذارد.

## چه چیزی دریافت می‌کنید

| بخش | رفتار |
|---|---|
| متن فارسی در چت | RTL و راست‌چین (بر اساس نسبت حروف فارسی؛ بلاک‌های «تفکرات» عمدتاً انگلیسی، LTR می‌مانند) |
| بلاک‌های کد و دستورهای ترمینال | LTR و دست‌نخورده |
| بلاک‌های ابزار (ترمینال / تفکر / ادیت) | ظاهر و چیدمان بلاک LTR می‌ماند؛ متن فارسی داخل بدنه RTL می‌شود |
| جدول‌ها | کاملاً RTL (ستون اول سمت راست)، مقادیر طولانی می‌شکنند به‌جای سرریز |
| حباب پیام کاربر | سمت راست؛ پیام دستیار سمت چپ |
| سایدبار اپ | کاملاً دست‌نخورده |

payload حین استریم‌شدن جواب مدل خودش را ترمیم می‌کند (اسکن با تأخیر ۲۰۰ میلی‌ثانیه)، پس متنی که وسط جواب تولید می‌شود بلافاصله درست می‌شود.

## نصب (۲ قدم)

### قدم ۱ — این ریپو را به‌عنوان مارکت‌پلیس پلاگین اضافه کنید

در ZCode به مسیر زیر بروید:

**Plugin Marketplace ← Add ← Add Plugin Marketplace**

و این آدرس را قرار دهید:

```
https://github.com/nimaone/zcode-rtl-plugin
```

### قدم ۲ — پلاگین را نصب کنید

مارکت‌پلیسی که اضافه کردید را باز کنید (تب **Personal**)، پلاگین **ZCode RTL Fix** را پیدا و **Install** کنید. بعد از نصب باید آن را در **Settings ← Plugin Management ← Installed** ببینید.

تمام. هیچ چیزی اجرا نمی‌شود و چیزی گوش نمی‌دهد — شما فقط یک کلید نصب کرده‌اید که خاموش است.

## روشن و خاموش کردن RTL

داخل چت ZCode دستور `/rtl-fix` را تایپ کنید (همراه پلاگین می‌آید):

| دستور | کاری می‌کند |
|---|---|
| `/rtl-fix on` | لایهٔ RTL را **همان لحظه** روشن می‌کند. اگر پورت دیباگ هنوز بسته باشد (اولین بار)، یک بار ZCode را با پورت ری‌استارت می‌کند (اسکریپت همراه `restart-zcode.ps1`) — session شما برمی‌گردد — و بعد روشنش می‌کند. |
| `/rtl-fix off` | لایهٔ RTL را **فوراً** خاموش می‌کند (صفحه تمیز ری‌لود می‌شود). پورت باز می‌ماند. |
| `/rtl-fix off hard` | سرور دیباگ را هم می‌بندد — بازگشت کامل به حالت پیش‌فرض حریم خصوصی (یک ری‌استارت). |
| `/rtl-fix status` | گزارش وضعیت: پورت باز/بسته، صفحات، فعال‌بودن payload. |

در پشت صحنه، این سوییچ `localStorage["zcodeRtl:enabled"]` و یک کلید درون‌صفحه‌ای (`window.__zcodeRtlSetEnabled(true|false)`) است؛ بعد از ری‌لود صفحه هم می‌ماند و فقط همان یک ری‌استارتِ اولِ بازکردن پورت، ری‌استارت واقعی می‌خواهد.

شورتکات‌های ZCode شما هرگز تغییر نمی‌کنند. اگر سبک «همیشه روشن» را ترجیح می‌دهید، یک بار ` --remote-debugging-port=9222` را به فیلد Target شورتکات ZCode اضافه کنید — از آن به بعد هوک SessionStart در هر session جدید RTL را خودکار برمی‌گرداند.

## نصب دستی

هر پلتفرمی:

```bash
# ابتدا ZCode را ببندید، سپس با پورت اجرا کنید
zcode --remote-debugging-port=9222 &        # یا مسیر کامل فایل اجرایی

# سوییچ زنده
node <مسیر پوشه پلاگین>/scripts/inject-rtl.mjs --set on
node <مسیر پوشه پلاگین>/scripts/inject-rtl.mjs --set off

# عیب‌یابی
node <مسیر پوشه پلاگین>/scripts/inject-rtl.mjs --status
node <مسیر پوشه پلاگین>/scripts/inject-rtl.mjs --eval "window.__zcodeRtlProcess ? 'ACTIVE' : 'ABSENT'"
```

## چطور کار می‌کند (خلاصه)

اسکریپت `scripts/inject-rtl.mjs` یک کلاینت CDP با Node و بدون هیچ وابستگی خارجی است. از طریق `http://127.0.0.1:9222/json/list` همهٔ صفحات رندرکننده را پیدا می‌کند، با WebSocket وصل می‌شود و `assets/zcode-rtl-fix.js` را داخل صفحه اجرا می‌کند. payload جهت هر المان را جداگانه تصمیم می‌گیرد: متن‌های فارسی‌غالب `direction: rtl` می‌گیرند، متن لاتین و کد LTR می‌مانند، سایدبار و ظاهر بلاک‌های ابزار صراحتاً مستثنا شده‌اند و یک `MutationObserver` نودهای تازهٔ استریم‌شده را دوباره پردازش می‌کند. چون فقط استایل زنده را دست می‌زند، هیچ‌وقت فایلی از اپ را روی دیسک تغییر نمی‌دهد.

**نکتهٔ امنیتی:** پورت دیباگ فقط روی `127.0.0.1` باز می‌شود و فقط از خود سیستم قابل دسترس است. آن را فوروارد نکنید. مگر اینکه خودتان RTL را روشن کنید، این پورت بسته است. این یک تزریق استایل سمت کاربر است، نه دستکاری اپ.

## رفع اشکال

| مشکل | راه‌حل |
|---|---|
| `/rtl-fix on` می‌گوید `PORT_CLOSED` | در اولین فعال‌سازی طبیعی است — خودِ دستور `restart-zcode.ps1` را اجرا می‌کند (یک ری‌استارت)، بعد دوباره `/rtl-fix on` بزنید |
| بلافاصله بعد از فعال‌سازی، فارسی هنوز LTR است | صفحه ممکن است هنوز در حال بازگشت باشد — یک بار دیگر `/rtl-fix on` بزنید یا پیام جدیدی شروع کنید |
| بعد از آپدیت ZCode چیدمان به‌هم ریخت | `/rtl-fix on`؛ اگر درست نشد یعنی DOM عوض شده — سلکتورهای payload را به‌روز کنید (بخش اسکیل) |
| می‌خواهید کاملاً حذف شود | `/rtl-fix off hard` |
